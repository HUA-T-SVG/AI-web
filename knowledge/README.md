## 1. 为什么产品需要这个东西

大模型不认识你们学科的口径。三个真实例子：

| 情况 | 大模型会怎么错 |
| --- | --- |
| 数据里 `-99` 表示「未回答」 | 它当成负九十九，**均值会被算成一个彻底错的数** |
| 「研究生」在教育统计口径下指硕士、不含博士 | 它按字面理解成「研究生包含博士」，归并结果错 |
| 学号 `001` 的前导零有意义 | 它当成数字 1，合并两张表时全对不上 |

这些都属于「**不写下来就一定会做错**」的知识。知识库就是写给它的说明书。

**为什么必须做**：这是产品「领域感知」叙事的全部依据。这块空着，产品就退化成通用数据清洗工具——而通用清洗工具已经有很多了。

---

## 2. 唯一的判据：pandas 会不会告诉你？

写之前先问自己这一句。**它决定了知识库值不值钱。**

> ✅ pandas **会**告诉你「这一列有 12 个缺失」→ **不用写**
> ✅ pandas **会**告诉你「均值是 23.4」→ **不用写**
> ❌ pandas **不会**告诉你「这一列的 `-99` 是缺失编码」→ **必须写**
> ❌ pandas **不会**告诉你「拒答和不知道是两种不同的缺失机制」→ **必须写**

凡是 `describe()`、`pandas-profiling` 能直接给出的，都不要写进来。写了只会让知识库看起来像常识汇编 —— 到时候评委会问「这跟现成工具有什么区别」，就答不上来了。

## 5. 逐列怎么填

一行 = 一条规则。11 列，逐列说明：

| 列名 | 怎么填 | 注意 |
| --- | --- | --- |
| `id` | 自己起个不重复的名字，如 `general-missing-01`、`psy-scale-03` | 用英文小写加短横线，别用中文；同一条规则以后改了内容，**id 不要改** |
| `标题` | 一句话说清这条规则管什么，20 字以内 | 如「负数编码表示未回答」 |
| `适用学科` | 7 选一：`通用` / `数据科学与大数据技术` / `心理学` / `教育学` / `公共卫生` / `社会学` / `经济学`（C 列有下拉） | 每条只填一个学科；拿不准就填 `通用` |
| `适用字段` | 这条规则管哪些列名，多个用逗号隔开，**把别名写全** | 见下方「第 6 节」——这是检索能不能命中的关键 |
| `触发条件` | 什么情况下该用这条规则 | 如「该列出现负数取值时」 |
| `规则内容` | 规则本身，用普通话写清楚，2–5 句 | 这是给大模型读的正文。不要用缩写、不要写「同上」 |
| `正例` | 一两个**正确**的例子，多个用 `；` 分隔 | 如 `硕士、研究生 → 硕士` |
| `反例` | 一两个**容易搞错**的例子，多个用 `；` 分隔 | 如 `硕士 与 博士 不可归并` |
| `来源` | 三行写：① 依据名称（发布机构 + 文档标题）② 公开 URL ③ 日期行 `核对日期：YYYY-MM-DD`（也接受「资料查阅日期」「复核日期」） | 如 `pandas 官方文档：read_csv` → `https://pandas.pydata.org/…` → `核对日期：2026-10-25`；查不到公开链接就写「待确认」并说明原因，不要空着 |
| `权威度` | 三选一：`国标` / `行业` / `团队经验` | 规则冲突时按这个排序 |
| `核验状态` | 两选一：`已核对` / `待核对` | 你写的所有条目**先填 `待核对`**，确认无误后再改成 `已核对` |

### 两个最容易被忽略、但答辩会被追问的列

- **`来源`**：评委问「这规则哪来的」，答「国标」和答「我问的导师」可信度完全不同。**不确定出处就写「待确认」，不要空着，也不要编。**
  有公开文档可引的，把来源写成三行（依据名称 / URL / 核对日期）：产品界面会把**第一个 URL** 做成可点击的来源链接、
  把日期行（`核对日期：YYYY-MM-DD`，也接受「资料查阅日期」「复核日期」）读成核验日期，评审能当场点开回查 —— 当前 **120 条来源带 URL**、121 条带日期行。
- **`反例`**：这是防止误合并的最后一道关口。写「硕士/研究生应归并」时，一定要写清「硕士/博士**不可**归并」。

## 6. 「适用字段」为什么是关键（请务必写全别名）

产品检索知识库时，**最可靠的信号是列名**，比语义相似度可靠得多。

但同一件事，不同人的表头写法完全不一样：

```
学历 / 受教育程度 / 文化程度 / 最高学历 / edu / education
```

如果你只写「学历」，那份表头写「文化程度」的数据就**召不回这条规则** —— 规则等于白写。

**填法**：把你能想到的写法都写上，逗号隔开。宁可多写几个别名，也不要漏。

## 7. 好坏对照

### ❌ 差的写法：一条里塞了三件事

| 标题 | 规则内容 |
| --- | --- |
| 数据常见问题 | 数据里常见的问题有缺失值、重复值、异常值，还有单位不统一、学历写法不一致、日期格式混乱，建议清洗时注意…… |

问题：检索时这条会跟任何查询都「有点像」，结果就是**每次都命中、每次都无关**，把真正有用的规则挤掉。

### ✅ 好的写法：一条一件事

| 标题 | 适用字段 | 规则内容 |
| --- | --- | --- |
| 负数编码表示未回答 | 缺失,未回答,NA | 国内大型调查数据常用负数区分未答原因：`-1` 不适用、`-2` 不知道、`-3` 拒答、`-9` 缺失。这些都不是真实数值。判定为缺失前必须先确认该列的负数含义，否则均值与分布都会被污染。 |

### ❌ 差的写法：只描述现象，不给依据和边界

| 规则内容 |
| --- |
| 学号列可能有前导零问题。 |

问题：没说清「怎么发现」「发现了该怎么办」，也没说反例，大模型只能自己猜。

### ✅ 好的写法

| 触发条件 | 规则内容 | 正例 | 反例 |
| --- | --- | --- | --- |
| 该列为标识列且取值为纯数字、长度固定 | 学号、编号这类标识列的前导零是有意义的（`001` ≠ `1`）。若某列所有值长度一致但个别值明显更短，通常是读取时被当成数字，前导零已丢失。处理方式是按目标长度左补零，而不是当异常值删除。 | `001`、`002`、`010` 长度一致，正常 | `1`、`2`、`10` 长度不齐，疑似前导零已丢 |

## 9. 交给我之后会发生什么

```
你填 Excel（knowledge/知识库模板.xlsx）
   ↓  ① 我跑一条命令：解析 + 校验
knowledge/entries/*.yaml          ← 产品真正读取的规则源文件
knowledge/reports/build-report.md ← 给你的回执：错在哪、警告什么、还差什么
   ↓  ② 同一条命令：算向量、建索引

knowledge/index/field-alias-taxonomy.json ← 字段别名归并结果
   ↓  ③ 产品每次分析时自动检索，把相关规则塞给大模型
```

**这条命令已经写好了**，你不用管它怎么跑：

```powershell
python knowledge/tools/build-index.py
```

**给我 Excel 之前，你可以自己先跑一次** `python knowledge/tools/build-index.py --check`：
它只校验、不写文件，**几秒内**告诉你哪一行哪一列有问题。比等我转发一轮快得多。

**①里我会退回来的情况**（会告诉你具体是哪一行、哪个字段）：

| 情况 | 为什么退回 |
| --- | --- |
| `id` 重复 | 后一条会覆盖前一条，静默丢内容 |
| `来源` 空着 | 答辩无法追溯，等于这条规则没有依据 |
| `规则内容` 超过 5 句或含「同上」 | 检索到的片段会不自洽 |
| `适用字段` 只有一个且是生僻写法 | 检索命不中，等于白写 |
| `权威度` / `核验状态` 写错字 | 排序与筛选会失序 |
| 归并类规则没写 `反例` | 缺反例是误合并的主要来源 |
| 学科名不在已登记列表里 | 不知道该写进哪个文件。**新学科先跟我说一声**，我登记 slug |
| sheet 名被改了 | 条目类别无法推断 |

**只提醒、不退回的**（会列在回执里，你自己判断）：

| 情况 | 为什么提醒 |
| --- | --- |
| 同一个字段别名被**同一类别**的多条规则用到 | 两条规则管同一个字段，冗余的可能性较高，值得确认 |
| 标题超过 30 字 / 触发条件超过 60 字 | 检索结果的展示名太长会看不清 |
| `核验状态 = 待核对` | 汇总成待办清单，答辩前要清掉 |
| 同一个字段族的别名散在一条规则里超过 5 个 | 请判断是不是同一族（`学号/工号/编号` 是，`性别/学历` 不是）。**候选清单，不是缺陷清单** |

> 同一别名被**跨类别**共用（一条「数据标准」+ 一条「清洗案例」都盖住该字段）**不会逐条提醒** ——
> 标准讲取值规范、案例讲踩过的坑，这是约定的分工，属于正常。只汇总一行报数量。

**回执在哪**：`knowledge/reports/build-report.md`。里面有**入库质量分**（升序排，
先看最后几行），逐项告诉你改哪里能把分提上去。

## 12. 常见问题

**Q：跑脚本报 `ModuleNotFoundError: No module named 'openpyxl'`。**
A：装依赖：`python -m pip install openpyxl PyYAML`。脚本需要它读 xlsx。

**Q：我把 Excel 的列顺序调了一下，会怎样？**
A：构建会中止并告诉你表头不符。**列顺序和列名都不要改** —— 那是脚本与文档共同依赖的约定。

**Q：我加了一张新的填写表（比如「统计口径」）。**
A：先跟我说。新增**填写表**要同时改脚本、`schema.md` 与 `IGNORED_SHEETS`，否则构建会以「未知 sheet」中止。
现在工作簿里的 5 张文档性 sheet（填写说明 / 字段说明 / 修订核验记录 / 本次扩展导航 / 学科目录）已经登记为忽略，加它们不用改代码。
