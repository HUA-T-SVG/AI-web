## 0. 一句话说清你要做什么

把「**不写下来，大模型就一定会做错**」的规矩，按模板填成**一行一条**。

---

## 1. 为什么产品需要这个东西

大模型不认识你们学科的口径。三个真实例子：

| 情况 | 大模型会怎么错 |
| --- | --- |
| 数据里 `-99` 表示「未回答」 | 它当成负九十九，**均值会被算成一个彻底错的数** |
| 「研究生」在教育统计口径下指硕士、不含博士 | 它按字面理解成「研究生包含博士」，归并结果错 |
| 学号 `001` 的前导零有意义 | 它当成数字 1，合并两张表时全对不上 |

这些都属于「**不写下来就一定会做错**」的知识。知识库就是写给它的说明书。

**为什么必须做**：这是产品「领域感知」叙事的全部依据。这块空着，产品就退化成通用数据清洗工具——而通用清洗工具已经有很多了。

---

## 2. 唯一的判据：pandas 会不会告诉你？

写之前先问自己这一句。**它决定了知识库值不值钱。**

> ✅ pandas **会**告诉你「这一列有 12 个缺失」→ **不用写**
> ✅ pandas **会**告诉你「均值是 23.4」→ **不用写**
> ❌ pandas **不会**告诉你「这一列的 `-99` 是缺失编码」→ **必须写**
> ❌ pandas **不会**告诉你「拒答和不知道是两种不同的缺失机制」→ **必须写**

凡是 `describe()`、`pandas-profiling` 能直接给出的，都不要写进来。写了只会让知识库看起来像常识汇编 —— 到时候评委会问「这跟现成工具有什么区别」，就答不上来了。

## 3. 你大概要花多少时间

**不用一次写完，也不追求数量。** 分批给我，我分批转。

| 阶段 | 内容 | 参考工作量 |
| --- | --- | --- |
| 第一步 | 审模板里预填的通用条目（我写的，可能有错） | 1–2 小时 |
| 第二步 | 挑**一个**你最熟的学科，补这个学科的条目 | 半天到一天 |
| 之后 | 跑真实数据时遇到新问题，随手往「清洗案例」里加一行 | 持续 |

**30–50 条就能让 RAG 演示成立。** 不是几百条才能开工。

## 4. 三个 sheet 分别填什么

打开 `knowledge/知识库模板.xlsx`，有三个填写用的 sheet：

| Sheet | 填什么 | 例子 |
| --- | --- | --- |
| **数据标准** | 字段的合法取值与编码规范 | 学历代码、民族代码、行政区划代码、性别代码 |
| **口径规则** | 统计口径、以及「知道才对」的判断 | 分类列不该算均值；量表分的天花板效应 |
| **清洗案例** | 你们遇到过的真实问题与处理方式 | 学号前导零丢失；单位混用 |

> 条目属于哪一类，由**它在哪个 sheet** 决定，所以没有单独的「类别」列。放错 sheet 了我会在转换时报错提醒你。

**模板里我已经预填了一批「适用学科 = 通用」的条目** —— 它们不针对任何学科，任何科研数据都会碰到。你们要做的是两件事：

1. **审一遍**：我是按通用情况写的，具体码值和阈值可能有错。你们是数据科学专业，判得出来。
2. **补学科条目**：挑**一个**最熟的学科补，不用全写。

在预填内容下面接着写新行就行。

## 5. 逐列怎么填

一行 = 一条规则。11 列，逐列说明：

| 列名 | 怎么填 | 注意 |
| --- | --- | --- |
| `id` | 自己起个不重复的名字，如 `general-missing-01`、`psy-scale-03` | 用英文小写加短横线，别用中文；同一条规则以后改了内容，**id 不要改** |
| `标题` | 一句话说清这条规则管什么，20 字以内 | 如「负数编码表示未回答」 |
| `适用学科` | `通用`，或学科名（`心理学` / `教育学` / `公共卫生` …） | 拿不准就填 `通用` |
| `适用字段` | 这条规则管哪些列名，多个用逗号隔开，**把别名写全** | 见下方「第 6 节」——这是检索能不能命中的关键 |
| `触发条件` | 什么情况下该用这条规则 | 如「该列出现负数取值时」 |
| `规则内容` | 规则本身，用普通话写清楚，2–5 句 | 这是给大模型读的正文。不要用缩写、不要写「同上」 |
| `正例` | 一两个**正确**的例子，多个用 `；` 分隔 | 如 `硕士、研究生 → 硕士` |
| `反例` | 一两个**容易搞错**的例子，多个用 `；` 分隔 | 如 `硕士 与 博士 不可归并` |
| `来源` | 这条规则的出处 | 如 `GB/T 4658-2006`、`国家统计局口径`、`导师口述`、`我们自己跑数据发现` |
| `权威度` | 三选一：`国标` / `行业` / `团队经验` | 规则冲突时按这个排序 |
| `核验状态` | 两选一：`已核对` / `待核对` | 你写的所有条目**先填 `待核对`**，确认无误后再改成 `已核对` |

### 两个最容易被忽略、但答辩会被追问的列

- **`来源`**：评委问「这规则哪来的」，答「国标」和答「我问的导师」可信度完全不同。**不确定出处就写「待确认」，不要空着，也不要编。**
- **`反例`**：这是防止误合并的最后一道关口。写「硕士/研究生应归并」时，一定要写清「硕士/博士**不可**归并」。

## 6. 「适用字段」为什么是关键（请务必写全别名）

产品检索知识库时，**最可靠的信号是列名**，比语义相似度可靠得多。

但同一件事，不同人的表头写法完全不一样：

```
学历 / 受教育程度 / 文化程度 / 最高学历 / edu / education
```

如果你只写「学历」，那份表头写「文化程度」的数据就**召不回这条规则** —— 规则等于白写。

**填法**：把你能想到的写法都写上，逗号隔开。宁可多写几个别名，也不要漏。

## 7. 好坏对照

### ❌ 差的写法：一条里塞了三件事

| 标题 | 规则内容 |
| --- | --- |
| 数据常见问题 | 数据里常见的问题有缺失值、重复值、异常值，还有单位不统一、学历写法不一致、日期格式混乱，建议清洗时注意…… |

问题：检索时这条会跟任何查询都「有点像」，结果就是**每次都命中、每次都无关**，把真正有用的规则挤掉。

### ✅ 好的写法：一条一件事

| 标题 | 适用字段 | 规则内容 |
| --- | --- | --- |
| 负数编码表示未回答 | 缺失,未回答,NA | 国内大型调查数据常用负数区分未答原因：`-1` 不适用、`-2` 不知道、`-3` 拒答、`-9` 缺失。这些都不是真实数值。判定为缺失前必须先确认该列的负数含义，否则均值与分布都会被污染。 |

### ❌ 差的写法：只描述现象，不给依据和边界

| 规则内容 |
| --- |
| 学号列可能有前导零问题。 |

问题：没说清「怎么发现」「发现了该怎么办」，也没说反例，大模型只能自己猜。

### ✅ 好的写法

| 触发条件 | 规则内容 | 正例 | 反例 |
| --- | --- | --- | --- |
| 该列为标识列且取值为纯数字、长度固定 | 学号、编号这类标识列的前导零是有意义的（`001` ≠ `1`）。若某列所有值长度一致但个别值明显更短，通常是读取时被当成数字，前导零已丢失。处理方式是按目标长度左补零，而不是当异常值删除。 | `001`、`002`、`010` 长度一致，正常 | `1`、`2`、`10` 长度不齐，疑似前导零已丢 |

## 9. 交给我之后会发生什么

```
你填 Excel
   ↓  ① 我读一遍：转成 YAML，同时校验
knowledge/entries/*.yaml     ← 产品真正读取的源文件
   ↓  ② 我跑一个脚本：算向量、建索引
knowledge/index/rules.json   ← 浏览器运行时加载
   ↓  ③ 产品每次分析时自动检索，把相关规则塞给大模型
```

**①里我会退回来的情况**（会告诉你具体是哪一行、哪个字段）：

| 情况 | 为什么退回 |
| --- | --- |
| `id` 重复 | 后一条会覆盖前一条，静默丢内容 |
| `来源` 空着 | 答辩无法追溯，等于这条规则没有依据 |
| `规则内容` 超过 5 句或含「同上」 | 检索到的片段会不自洽 |
| `适用字段` 只有一个且是生僻写法 | 检索命不中，等于白写 |
| 同一个 `id` 内容变了但 `来源` 没变 | 需要你确认是有意修订还是笔误 |

**修订已有条目**：直接改 Excel 对应行，`id` 保持不变，我重新转换时会覆盖。
