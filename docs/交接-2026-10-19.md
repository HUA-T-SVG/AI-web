## 4 本机环境与已知坑

### 4.1 硬约束

| 约束 | 说明 |
| --- | --- |
| **不写 C 盘** | 用户要求。`$env:TEMP='D:\tmp'`、`$env:TMP='D:\tmp'` 每次会话先设 |
| pnpm | `D:\npm-global\pnpm.cmd`（不是全局 `pnpm`） |
| Playwright | `$env:PLAYWRIGHT_BROWSERS_PATH='D:\ms-playwright'` |
| Node | DSH 自带 Node 可用；项目 `.node-version` = 24 |

### 4.2 生成文档需要的三个路径（本机 DSH 运行时，换机器要跟着换）

```powershell
$env:PYTHON       = 'C:\Users\lt\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'
$env:LO_KIT_NODE  = 'D:\dsh-harness\resources\runtime\primary-runtime\dependencies\node\bin\node.exe'
$env:LO_KIT_CLI   = 'D:\dsh-harness\resources\app.asar.unpacked\dsh\node_modules\@deepseek-ai\libreoffice-kit\lib\cli.js'
```

没有 LibreOffice 时 `doc:build` 只出 Word 并提示，不算失败。

### 4.3 踩过的坑（都会再遇到）

1. **`edit` 偶发 `ReplaceFileW EIO (Win32 1175)`** —— VS Code 文件监视导致，**原样重试即可**，不是内容问题。
2. **LibreOffice 不覆盖已存在的输出** —— 第二次 `doc:build` 必失败。脚本已修（先 `unlinkSync`）；改脚本后**必须连跑两次验证**。
3. **全量单测在机器有负载时会红，但用例零失败** —— 看输出里的 `Errors 1 error` 与 `Timeout calling "onTaskUpdate"`；根因是 `src/core/evaluate/systemEval.test.ts`（L5）单文件在负载下要 95 秒，把 vitest 的 worker 心跳拖超时。**别加 retry、别改断言**。
4. **全量单测还慢时先查有没有残留 dev server** —— 上一轮的假红就是我自己起的 `next dev` 没关（占 3000 端口吃 CPU）。
5. **`git push` 到 GitHub 经常超时** —— `Failed to connect to github.com port 443: Timed out`，重试 4–6 次即可（凭证已缓存在 GCM，不要重新登录）。
6. **Playwright 截图后记得 `browser.close()`**，否则残留 chromium 进程会影响性能用例。
7. **给文档加截图前先裁空白** —— 线上页面下方大量白底，直接入 PDF 会吃掉半页（用 Pillow 从下往上找第一行有内容的行）。
8. **不要在文档里写死提交数**（现在是「132 提交」，实际已 143）—— 每次提交都会让它过期，建议改成「保留完整提交历史，未 squash」。
9. **`doc:build` 的 PDF 那一步会在受限沙箱里因 TEMP 在仓库外失败** —— LibreOffice Kit 要 `mkdtemp`，写到 `D:\tmp` 被拒（`EPERM: operation not permitted, mkdtemp`），Word 那一步不受影响。把 `$env:TEMP`/`$env:TMP` 指到**仓库内**的临时目录、跑完删掉即可，不需要申请更大权限。
