## 4 不能破坏的约定（第三轮新增）

1. **示例数据必须走同一条 `loadFile` 路径**，且 `isSample` 要跟到工作页与报告；
   不要把示例数据另造一份并直接塞进 store。
2. **报告只从已有产物组装**：`provenance` / `changeSummary` / `reviewItems`。
   报告与界面必须说同一句话，否则「导出与界面不一致」就是必然。
3. **PDF 是打印路径**，文案不能写成「直接生成 PDF」；Word 用真实 `.docx`，不要退回 `.doc`。
4. **打印样式依赖 `.print-report`**：报告根节点必须有这个 class，否则打印会整页输出。
5. **长文本不能只靠 `title`**：表格单元格点击看全文，问题卡片展开看完整描述。
6. **44px 只在 <768px 生效**（`max-md:min-h-11`），不要改桌面尺寸。
7. **E2E 锁住的文案**：`执行清洗（N 条）`、`数据预览`、`共 N 行 × M 列`、导航名、
   `清洗后数据（CSV）` / `处理留痕（JSON）` / `pandas 脚本`、`撤销上一步`。
8. **测试数字**：830 / 8 / 70 与 92 / 1；改动要同步四份文档 + `scripts/check-doc-facts.mjs`，
   然后 `pnpm doc:build` + `pnpm check:doc`。

## 5 已知留存风险

- **PDF 需用户在打印对话框里选「另存为 PDF」**；没有做服务端/字体嵌入的直接 PDF 下载。
- **`docx` 依赖约 1–2 MB（按需 chunk）**：已用动态 import 隔离，但 `pnpm build` 时 export 页
  会多一个按需 chunk；首屏不应包含它。
- **打印样式用了 `body:has(.print-report)`**：现代浏览器支持；旧浏览器退化行为是整页打印，
  不会出现空白页。
- **E2E 的报告用例覆盖「导入未清洗」状态**；带清洗动作与人工决定的报告内容由
  `report.test.ts` 的固定输入钉住，未走完整 AI 流程。
- 移动端报告预览较长，导出页比之前多一屏左右。
- 语义归并线上仍为 char-ngram 哈希后端，检查页降级提示照旧（历史事项，不属三轮范围）。
- 44px 只覆盖按钮与导航；表格单元格/表单输入未逐个抬高（触屏上仍可点，但小于 44px）。
- 列宽调整与长文本弹层没有 E2E 覆盖（列宽有键盘断言，长文本弹层仅人工冒烟）。

## 6 第三轮之后的热修（2026-10-23 ~ 10-24）

### 6.1 中断工具调用导致「Tool results are missing」

**现象**：点「从执行检查重试」后页面报 `调用大模型时出错：Tool results are missing for
tool calls call_…`，模型一次都没被调用。

**根因**：流在工具调用之后中断时，助手消息里留下了 `tool-call`，但 `tool-result` 没回填。
AI SDK 在把历史消息转换成模型输入时发现「有调用、没结果」，直接抛
`MissingToolResultsError`。第二轮实现的重试走 `sendMessage`，会保留这条半截的助手消息，
于是必然撞上；原来的「重试一次」走 `regenerate()`，会先删掉最后一条助手消息，所以没暴露。

**修法**：
- `agentPhase.ts` 新增 `findDanglingToolCalls` / `repairDanglingToolCalls`：发送前把残留调用
  补成 `output-error`（说明「上一次分析在这里中断」），历史消息重新合法；再用 `setMessages`
  同步写回，随后 `sendMessage`。所有发送入口（表单、按计划执行、按环节重试）都走这一层。
- `errors.ts` 增加该错误的归一化：标题「上一次分析没有正常收尾」，说明是中断残留、
  重试会先补齐，不再显示英文原文。
- 单测 +5（工具调用识别/修复），E2E +1（模拟 tool-input-start 后断流，再次发送不报错）。

**代价**：修复后的历史里那条调用显示为失败，模型会看到「这项没跑完」；
这是如实记录，比删掉它更接近实际发生的事。

### 6.2 留痕 JSON 与界面说明不一致

**现象**：下载「处理留痕（JSON）」后，文件里只有动作（steps）、指纹与环境信息；
界面按钮下却写着「动作、人工决定与数据指纹」。被拒绝的建议、用户填写的理由、
只确认不改数据的决定都不在文件里。

**根因**：`Provenance` 类型只有 `steps`，没有承载人工决定的字段；可读报告另外从
`reviewStore` 取，所以界面/报告有、JSON 没有。

**修法**：`Provenance` 新增 `decisions`（标题/严重度/决定/理由/原建议/改后参数），
`buildProvenance` 接收并原样写入；ExportPanel 把 `reviewItems` 映射后传入。
没填理由写 `null`（不用空字符串），区分「没写」与「同意」。单测 +2 钉住
「拒绝也必须留下原因」与「无决定时是空数组」。

### 6.3 手机上点问题卡片，展开内容被切走

**现象**：<768px 时点问题卡片会展开长描述，但检查页同时自动切到「判定依据」tab，
问题列表被 CSS 隐藏，刚展开的内容看不到。

**根因**：`selectIssue` 同时做了「选中」和「切 tab」；而点卡片本身还承担「展开」。

**修法**：`selectIssue` 不再自动切 tab；展开留在问题列表，想看判定依据时点上方 tab。
mobile-a11y E2E 改为直接断言「点卡片后问题列表 tab 仍选中、展开区可见」，不再靠
「切回来再断言」的兼容写法。

### 6.4 刷新后示例数据标记丢失

**现象**：点「体验示例数据」后刷新，数据回来了，但「示例数据」徽章和「当前是示例数据」
提示消失，报告里却仍写着「示例-科研问卷.csv」。

**根因**：`isSample` 只在内存 store 里，缓存只存 dataset/meta/savedAt/dataVersion。

**修法**：缓存结构升到 v3，持久化 `isSample`；`loadSample` 在落盘成功后
才置内存标记（标记一出现，刷新就已经能读到它）；恢复时把 `isSample` 一起恢复。
v2 旧缓存仍可读（缺字段按 false 处理），不因为一个提示标记丢掉用户已导入的数据。
单测 +2（示例标记往返 / v2 兼容），E2E +1（刷新后仍是示例）。

### 6.5 刷新后清洗与人工决定丢失，UI 没明说

**现象**：缓存只存导入数据；刷新后清洗动作、撤销记录、人工复核理由全部重置，
但恢复提示只说「这是上次导入的数据」。

**根因**：这是第二轮「只存 Dataset、不存结论」的有意取舍，但取舍没有告知用户。

**修法**：恢复提示条明确写出「刷新只恢复导入的原始数据：清洗动作、撤销记录与人工复核
理由不会保留，需要时请重新分析」。E2E 断言提示条包含这句话。

### 6.6 全量 E2E 冷启动假红

**现象**：清掉 `.next` 后第一次跑全量 E2E，会出现一批「数据预览 15 秒没出现」的失败；
重跑全绿。不是产品 bug，但会让人误判「改坏了」。

**根因**：Next dev 按需编译。多个页面同时首访时，路由编译 + 每个页面建检查 Worker 叠加，
把首次剖析拖到十几秒；此外上传按钮在 hydration 前就存在，`setInputFiles` 触发的 change
没有监听器，文件被静默丢掉。

**修法**：
- 应用在 `EmbeddingPrefetch` 的 effect 里写 `data-app-hydrated`，E2E 上传前等它；
- 新增 `tests/e2e/warmup.setup.ts` 作为 **setup project**：先访问五个路由、上传一次并等检查完成，
  把所有路由与 Worker 编译跑热，再让被测用例开始；
- E2E 串行（`workers: 1`），断言等待 15 秒。
- **验证方式**：删掉 `.next` 后从零跑全量，80 passed / 1 skipped（比只跑“温缓存”更有说服力）。

### 6.7 工具链：lint 与 perf 偶发红

**lint**：Next 16 移除了 `next lint`，旧配置还经 `FlatCompat` 包装 Next 的 shareable config，
结果直接抛 `Converting circular structure to JSON`。修法：`eslint.config.mjs` 改为直接
展开 `eslint-config-next/core-web-vitals` 与 `/typescript`（它们本身就是 flat config 数组），
`package.json` 的 `lint` 改为 `eslint .`。同时修掉 4 个真实 error
（两处 `prefer-const`、两个测试辅助函数误用 `use*` 前缀触发 hooks 规则）。
现在 `pnpm lint` 退出码 0（0 error / 201 warning，warnings 暂不阻断）。

**perf 偶发红**：`perf.test.ts` 断言 5 万×50 剖析 < 3 秒；与其他测试文件**并行**时
CPU 竞争会把它推到 3 秒以上，历史上还出现过 worker RPC 心跳超时。
修法：`vitest.config.ts` 设 `fileParallelism: false`（测试文件串行，约 7 秒 → 28 秒），
**断言与预算未动、没有加 retry**。

### 6.8 导出的 pandas 脚本在连续归并时方向反转

**现象**：原始类别 `a,b,b,c,c,c,c`，先归并 a/b 再归并 b/c，界面最终全部为 c；
导出的脚本却得到三个 a、四个 c。

**根因**：脚本生成只拿到**最终数据**，每一步又用最终数据的计数重新选 winner。
第一步 a/b 在最终数据里都已消失（都是 0 次），并列取组内第一个 → 选成 a，方向反了；
界面执行时用的是**当时**的计数（b 胜），所以结果不同。

**修法**：
- `AppliedAction` 新增 `mergeResolution`：执行时记录每组实际 winner 与「非 winner → winner」
  映射，组按执行顺序保留（重叠组不能压平成一张 dict，`{a:b,b:c}` 同时替换 ≠ 先 a→b 再 b→c）。
- `buildPandasScript` 接收 `applied`，有执行记录时**只按记录重放**，不再重算方向；
  没有 `applied` 的旧调用方仍走原逻辑（产品路径已全部传）。
- 留痕 JSON 的 `steps` 也带 `mergeResolution`，导出的文件能直接核对每一步的方向。
- 单测 +3：执行器记录映射、脚本重放（含 a/b→b/c 回归）、provenance 的 JSON/脚本一致；
  `pandas-runtime.test.ts` 也改为传 `applied`（有 pandas 时会真跑脚本逐格比对）。

### 6.9 AI 分析仍读最初导入的数据，却按当前版本记建议

**现象**：清洗后再次分析，AI 摘要与工具检查的仍是 `parseResult.dataset`（最初导入的数据），
但 `beginRun` 记录的是当前 `dataVersion` —— 结论说的旧数据、却标成当前版本，版本保护失效。

**根因**：第二轮新增 `workingDataset/workingProfile` 后，只有检查页换过去了；
`AgentPanel` 的摘要、工具执行、画像仍读 `parseResult.dataset` / `profile`。

**修法**：
- AI 侧统一读 `workingDataset` / `workingProfile`，不再回退到原始数据画像；
  画像重算期间提交按钮禁用并显示「正在按数据版本 vN 重新计算画像」。
- 本轮开始时**冻结数据快照**（dataset/profile/fileName/version）到 ref：
  摘要、`onToolCall` 的工具执行、`beginRun` 版本全部来自同一份快照；
  分析中途页面状态变化不会让工具换一份数据。
- E2E +1：清洗删除重复行后再次分析，拦截请求体断言摘要为「规模：6 行 × 5 列」
  而不是原始 7 行。

### 6.10 去重按 `String()` 判等，类型不同却被误删

**现象**：同一列里数字 `1` 与文本 `"1"` 被当成重复记录，只保留一条；
`null` 与文本 `"null"`、含分隔符的字段拼接也可能碰撞。导出的 pandas 脚本
与界面去重口径还可能不一致。

**根因**：`remove_duplicates` 用 `String(value)` 拼接判重键，类型信息与字段边界都丢了。

**修法**：
- 新增 `core/encoding.ts`：`encodeCellValue` 按类型编码（缺失/布尔/数字/字符串），
  字符串带长度前缀；`encodeRowKey` 再给每个单元格编码套长度前缀，字段边界不会串位。
  数据指纹也改为复用这一份编码，避免两套判等规则再次分叉。
- 执行器与 `rowKey` 都改用 `encodeRowKey`：`1` ≠ `"1"`、`null` ≠ `"null"`，
  值里含 `\u0000` 也不会把两行拼成同一个键。
- 导出的 pandas 脚本不再用 `drop_duplicates` 的默认相等，改为生成 `_dedupe_key`：
  缺失/布尔/字符串/数字分组后转 tuple 再交给 `duplicated()`，与界面口径一致。
- 单测 +3：数字/文本、缺失/文本、含分隔符的字段边界；脚本生成测试改为断言
  类型化判重代码，不再断言 `drop_duplicates`。
