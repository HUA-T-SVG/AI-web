  **GitHub REST API 增量重放**：以「本地与远端内容等价的提交」为锚，只重放新提交。

## 6. 已知局限（答辩要如实讲的）

- 方法草稿**不含逐项检查检出数**（避免与 `checks.counts` 形成第二套数字；需要时另扩类型）；
- 规则依据只列用户配置的 `user-range:*`；知识库只给规模与核验数，**不列具体规则编号**
  （检索命中不落留痕，不能声称每条建议来自某条规则）；
- 语义归并是端侧模型单独跑的：模型不可用时草稿写「只跑了字面/结构规则」；
  文档图 2 即降级态截图（图 6 保留此前「已就绪」的线上证据）；
- `check:doc` 是**文档互证**（数字能在仓库产物里找到出处），不会真的去跑测试对数字；
- L4 Agent 层仍有 3/12 轮次截断（T11 产品决策）、未接 CI、无覆盖率、鉴权未做；
- 线上有真实模型的端到端证据来自手工冒烟，E2E 默认掐断端侧模型（稳定性优先）。
