## 3. 最近几轮修了什么

### A1：留痕 JSON 补人工决定（提交 `9f142e9`）

`Provenance` 新增 `decisions`；`reviewItems` 映射为 `ProvenanceDecision[]`（标题/严重度/决定/理由/原建议/改后参数）。JSON、可读报告、Word 现在口径一致。没填理由写 `null`，区分“没写”与“同意”。

### A2：手机端点问题卡片不再被 tab 切走（提交 `9f142e9`）

`selectIssue` 不再自动切到「判定依据」tab；展开内容留在问题列表。E2E 断言点击后问题列表 tab 仍选中、展开区可见。

### A3：刷新后示例数据标记丢失（提交 `7af057e`）

缓存结构升到 v3，持久化 `isSample`；`loadSample` 先落盘再置内存标记；恢复时一起恢复。v2 旧缓存仍可读（缺字段按 false），不因一个提示标记丢掉已导入数据。

### A4：刷新后清洗/人工决定丢失，UI 没明说（提交 `7af057e`）

`RestoreNotice` 明确写出：“刷新只恢复导入的原始数据：清洗动作、撤销记录与人工复核理由不会保留，需要时请重新分析。”

### A5：全量 E2E 冷启动假红（提交 `465bec0`）

根因：Next dev 按需编译 + 多个页面同时首访 + hydration 前 `setInputFiles` 丢文件。
修法：

- `EmbeddingPrefetch` 的 effect 写 `document.documentElement.dataset.appHydrated = 'true'`；
- helpers 提供 `waitForAppHydrated()` / `gotoHydrated()`，上传前先等它；
- `tests/e2e/warmup.setup.ts` 作为 setup project，先访问五个路由、上传一次并等检查完成；
- E2E 串行，`expect.timeout = 15_000`。
- **验证方式**：删掉整个 `.next` 后从零跑全量，80 passed / 1 skipped（不是只跑温缓存）。

### A6：工具链（提交 `465bec0`）

- `pnpm lint`：`eslint.config.mjs` 改为直接展开 `eslint-config-next/core-web-vitals` 与 `/typescript`（Next 16 本身就是 flat config 数组），`package.json` 的 `lint` 改为 `eslint .`。旧 `FlatCompat` 会抛 `Converting circular structure to JSON`。顺带修了 4 个真实 error（2 个 `prefer-const`、2 个测试辅助函数 `use*` 前缀触发 hooks 规则）。
- `perf.test.ts` 偶发红：根因是测试**文件并行**时 CPU 竞争；`vitest.config.ts` 设 `fileParallelism: false`（约 7 秒 → 27 秒），**断言和 3 秒预算未动、没有加 retry**。

### 脚本归并方向（提交 `9aee10b`）

现象：`a,b,b,c,c,c,c`，先并 a/b 再并 b/c，界面全 c，导出的 pandas 脚本却得到三个 a。
根因：脚本生成拿**最终数据**重算每步 winner；a/b 在最终数据里都消失（0 次），并列取第一个 a，方向反了。
修法：

- `AppliedAction.mergeResolution` 记录执行时每组实际 winner 与映射，组按顺序保留；
- `buildPandasScript` 接收 `applied`，有记录时**只按记录重放**；
- 留痕 JSON 的 `steps[]` 也带 `mergeResolution`；
- 单测 +3；`pandas-runtime.test.ts` 改为传 `applied`。

### AI 分析读工作数据（提交 `fba7c5d`）

现象：清洗后再次分析，AI 摘要/工具仍读 `parseResult.dataset` 和原始 `profile`，但 `beginRun` 记录当前 `dataVersion`，版本保护失效。
修法：

- `AgentPanel` 的摘要、工具执行、画像统一读 `workingDataset` / `workingProfile`；
- 本轮开始时冻结快照 `{dataset, profile, fileName, version}` 到 ref，工具与 `beginRun` 都用同一份；
- `workingProfile` 重算期间提交按钮禁用并显示「正在按数据版本 vN 重新计算画像」；
- E2E +1：清洗删行后二次分析，请求体摘要为 6 行而不是原始 7 行。

### 去重判重键（提交 `f86f2c2`，对齐后成为本文件的祖父提交）

现象：数字 `1` 与文本 `"1"` 被当重复；`null` 与 `"null"`、含分隔符的字段也可能碰撞。
修法：

- 新增 `src/core/encoding.ts`：`encodeCellValue`（缺失/布尔/数字/字符串，字符串带长度前缀）+ `encodeRowKey`（每个编码再定界）；
- 执行器 `remove_duplicates`、`rowKey`、数据指纹统一复用；
- pandas 脚本不再用 `drop_duplicates` 默认相等，改为生成 `_dedupe_key` + tuple `duplicated()`；
- 单测 +3；线上用 Excel（数字 1 / 文本 "1" 各两条）冒烟：去重后保留 2 行，脚本包含 `_dedupe_key`。

## 6. Git / 部署现状（重要）

**本地/远端分叉已对齐（2026-10-25）**：

- 旧的远端 `main = f86f2c2` 与旧的本地 `HEAD = 6d29018` 内容等价，只差 4 份 md 的 CRLF/LF 存储
  （代码 blob 一致），所以看上去像「两个不同的提交」。本轮以 `f86f2c2` 为父，先提交
  「统一 4 份 md 行尾为 LF」，再提交本文件；**远端与本地现在是同一条历史**。
- 旧提交 `6d29018` 保留在本地分支 `backup/main-6d29018`，未推送。
- 以后改这 4 份 md 时留意行尾：仓库 `core.autocrlf` 是 true，提交前用 `git status` 确认没有
  意外的整文件换行 diff。
- **不要 force push 远端**。

网络兜底（还会用到）：

1. 本地 CONNECT 代理：`.tmp/gh-proxy.mjs`，`GH_TARGET_IP` 指向可达 IP（140.82.112.3 / 140.82.113.3 等），git 用：
   ```powershell
   git -c http.proxy=http://127.0.0.1:8899 -c https.proxy=http://127.0.0.1:8899 `
       -c http.version=HTTP/1.1 -c http.sslBackend=openssl push origin main
   ```
2. 当代理也失败时，用 GitHub REST API 创建 blob/tree/commit 再 PATCH ref（`.tmp/push-api.mjs` / `.tmp/align-final.mjs`）。token 从 Windows 凭据管理器取，不落盘、不打印：
   ```powershell
   $cred = ("protocol=https`nhost=github.com`n`n" | git credential fill)
   $token = (($cred -split "`n") | Where-Object { $_ -like 'password=*' } | Select-Object -First 1) -replace '^password=',''
   $env:GH_TOKEN = $token
   node .tmp/push-api.mjs
   ```
   **两条实测坑**：
   - `api.github.com` 的 TCP 建连常超过 10 秒，Node 内置 `fetch` 默认 10 秒会报
     `fetch failed`（此时用 curl / `Invoke-RestMethod` 却是通的）。改用 `node:https` 显式
     放大连接超时并重试，或先设 `--dns-result-order=ipv4first`。
   - 用 REST API 重建本地提交时，**远端提交 SHA 与本地不保证一致**（服务端对消息结尾换行、
     日期时区的序列化与本地 git 不完全相同）。它适合「把内容推到远端」，不适合要求提交号一致；
     能用 `git fetch` / `git push` 时优先走 git。
- `.tmp/` 是忽略目录；`push-api.mjs`、`gh-proxy.mjs`、`align-final.mjs`、冒烟脚本都在里面，不要提交。
- `docs/部署指南.docx` 未跟踪，**不要提交**。
