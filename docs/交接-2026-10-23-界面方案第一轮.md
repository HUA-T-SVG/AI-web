## 3. 按页面改了什么

### 3.1 全局（所有工作页）

- 新增 [`DataContextBar`](../src/ui/components/DataContextBar.tsx)：显示文件名、行×列、
  `数据版本 vN`、检查状态（检查完成/检查中/结论未知/尚未检查）、是否本机恢复。
- 它挂在 [`AppShell`](../src/ui/components/AppShell.tsx) 的 `RestoreNotice` 之后，**在 `/import` 隐藏**
  （导入页自己已有文件栏）。
- 为保证「文件名只出现一次」：检查页 PageHeader 不再显示文件名，
  [`QualityReportPanel`](../src/ui/components/QualityReportPanel.tsx) 也删掉了「文件名：…」。
  E2E 里 `/messy-survey.csv/` 的 `getByText` 依赖这个唯一性，**不要加回重复文件名**。
- `datasetStore` 新增 `dataVersion`（每次 `adoptDataset` +1，`reset` 归 0）。
  **注意：它只活在当前会话，不写 IndexedDB**；刷新后从 0 开始、恢复数据后是 v1。
  如果第二轮要做「旧结论按版本失效」，需要把版本随缓存一起持久化，并想清楚「同一份文件重新导入算不算新版本」。
- 视觉微调（按方案表格）：`CardTitle` 18px、数据表 13px、侧栏 232px、
  `prefers-reduced-motion` 下关闭过渡动画。

### 3.2 数据导入

- 「接下来」从三张大卡收成一条轻量操作条（[`NextSteps`](../src/app/import/page.tsx)），
  数据概况/列画像/预览改为整宽，减少嵌套卡片。
- 本机暂存说明前置为一行链接，指向底部 [`LocalDataCard`](../src/ui/components/LocalDataCard.tsx)
  （给它加了 `id="local-data"`）。
- **没做**：示例数据入口、点击字段定位表格列、列宽调整、字段搜索（第三轮）。

### 3.3 质量检查（核心页）

  明确写「已复核含接受、修改与拒绝，不等于已修复」。
- 中：左 [`IssueList`](../src/ui/components/IssueList.tsx)，右 [`IssueDetailPanel`](../src/ui/components/IssueDetailPanel.tsx)。

  表尾仍保留 `共 N 行 × M 列`，过滤时追加 `· 当前显示 K 行`。

### 3.5 报告与导出

### 3.6 AI 分析

## 4. 不能破坏的约定（改 UI 前先看）

1. **文件名只出现一次**（见 §3.1）。在 `/check /analysis /rules /export` 上的文件名由 `DataContextBar` 提供；
   在 `/import` 由文件栏提供。
2. **检查页「证据」与「判定依据」是两个词**：展开的 `IssueCard` 里是「证据」，右侧详情是「判定依据」。
   E2E `展开问题条目能看到证据与建议` 依赖前者唯一。
3. **问题列表默认按严重度降序**。技术文档图 7 的说明「第 4 条是语义级候选」依赖它；
   改排序会同时改坏文档叙述。
4. **检查页不默认选中问题**；否则标题/描述在列表与详情重复，Playwright strict mode 会红。
5. **`DataTable` 表尾文案** `共 N 行 × M 列` 是 E2E 与截图断言的一部分；`visibleRows` 只能追加后缀。
6. **AI 检查计划复选框的 `aria-label`** 保持 `执行 ${checkId}${（列名）}`；可见文字才可以中文化。
7. **审核动作按钮名**仍是 `接受 / 修改 / 拒绝`。设计文档建议改用「接受建议 / 修改参数 / 保留原样」，
   但 E2E 与既有文案都用现在这套；如果改，必须同步改测试与文档，不要只改 UI。
8. **测试数字**：单测 **789 passed / 8 skipped / 67 文件**，E2E **86 passed / 1 skipped**。
   任何测试数量变化都要同时改 `docs/技术文档.md`、`docs/开发交接说明.md`、`docs/交接-2026-10-21.md`
   与 `scripts/check-doc-facts.mjs`，然后 `pnpm doc:build` + `pnpm check:doc`。
9. **技术文档为 30 页**（上限 30，已顶满），`check:doc` 30 项全过。再加内容必须先压缩别处。
10. **指纹口径变更**：`f5b1490` 起改为「整行编码后排序、保留类型」。旧留痕里的指纹不能与新版本互比；
    对比时看 `environment.appVersion`。不要为了兼容旧值把行级对应关系又丢掉。
11. **`docs/部署指南.docx` 是未跟踪文件，不属于仓库**，提交时不要 `git add .`。

## 6. 验证与部署

### 6.1 四道门禁（每次提交前）

```powershell
$env:TEMP='D:\tmp'; $env:TMP='D:\tmp'; $env:PLAYWRIGHT_BROWSERS_PATH='D:\ms-playwright'

node_modules/.bin/tsc.cmd --noEmit     # 期望 exit 0

pnpm test:e2e                          # 86 passed / 1 skipped，串行约 1.5 分钟
pnpm build                             # 成功
```

E2E 说明：

- 浏览器必须访问 `http://localhost:3000`（Next 16 会拒绝 `127.0.0.1` 的 dev 资源）。
- E2E 默认**掐断端侧模型**，所以检查页显示「语义归并不可用」是预期的降级路径；不要把它当 bug。
- 全量 E2E 偶发 `persistence.spec` 超时已修（旧断言在 `/check` 等 `/共 \d+ 行/`，那文本只存在于导入页，
  会随导航快慢随机红）。不要退回那条断言。
- 跑完 E2E 后 `git checkout -- knowledge/reports/ next-env.d.ts`，避免把测试产物带进提交。

### 6.2 部署与线上检查

```powershell
git -c http.sslBackend=openssl push origin main
```

- 网络可能 `schannel` 报错，这是已知环境问题；用上面的 `sslBackend=openssl`，失败重试。
- Vercel 自动部署；用 GitHub commit status API 看 `context === 'Vercel'` 到 `success`。
- 部署后逐页 `curl -o NUL -w '%{http_code}'` 检查五个路由；必要时用 Playwright 做一次线上交互冒烟
  （导入 → 检查页选中问题 → 判定依据/仅看相关记录 → 规则库筛选 → 导出清洗前后/遗留风险）。

### 6.3 编辑时的一个坑

`pnpm dev` 运行期间批量改文件可能报 `ReplaceFileW EIO (Win32 1175)`。
先停 dev server，改完再开；不要把失败当成文件损坏。

### 第二轮（接通核心核对流程）

1. **执行前改参预览**：改参数/接受建议后、真正执行前，显示将要改多少单元格/删多少行；
   目前只有执行后的 `changedCells` 摘要。
2. **停止与按失败环节重试**：Agent 运行中停止；失败时按「计划/检查/汇总」环节重试，
   不要只给一个笼统的「重新开始」。
3. **旧结论按数据版本失效**：`dataVersion` 目前只是展示值、且刷新后重置；
   要真正做失效，需要持久化版本 + 在检查/审阅/AI 结论上记录版本，并在当前版本不匹配时明确标注。
4. **撤销后重新检查联动**：撤销后应重新检查、更新问题清单与导出结论；现在撤销只回退数据/动作。
5. **移动端底部操作区**（<768px）：确认/执行按钮固定在底部，不遮挡内容；
   768–1279px 侧栏可收起（目前 <768 才换顶部导航）。
6. **无障碍细节**：严重程度文字+颜色（已做颜色+文字）、长文本不能只靠 hover、
   键盘焦点（已有全局 `:focus-visible`）。
