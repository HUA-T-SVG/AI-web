## 一、一句话讲清这个作品

> 它是一个**面向高校科研团队的数据质量治理 Agent**：数据在浏览器本地解析和检查，AI 只拿结构摘要；AI 提出结论与建议，但**每一条都要人核对、人确认**，清洗留痕、报告可复现。

## 三、示例（就用这一套，已验证可跑通）

### 3.1 演示数据：10 行 × 4 列合成问卷（`fixture.csv`）

```csv
学号,成绩,学历,单位
001,85,本科,mg
002,90,硕士,MG
003,999,硕士,mg
004,78,本科,g
005,,博士,mg
006,88,研究生,mg
007,65,本科,g
008,0999,硕士,mg
009,72,本科,mg
010,95,硕士,MG
```

> 这份数据里故意埋了：缺考码 `999`、前导零 `0999`、空成绩、`博士/研究生` 等不在允许清单的写法、单位大小写不一致。示例是**合成数据**，界面会标注「示例数据」。

### 3.2 数据字典文本（4 行，复制粘贴）

```text
成绩：允许范围 0–100 分。
成绩：999 表示缺考。
学历：只允许本科、硕士。
单位：只允许 mg、g。
```

> **录前必查**：点「AI 提取候选规则」后，候选统计应是「共 4 条：数值范围 1 · 允许取值 2 · 缺失占位码 1 · 明确有效值 0」。如果少了「缺失占位码」，重提一次；仍缺就手动补，否则后面不会出现「对比清洗口径」。

### 3.3 分析提示词（一轮完成；实测约 46 秒）

```text
这份科研问卷有 10 行数据。请分析【成绩】和【单位】两列。先提交检查计划，等我确认后再执行。
逐条提交结论，每条必须填 disposition，三种各出现一次：
1. inform_only：说明本批数据字典已确认成绩的允许范围 0–100、999 为缺考码（这条只是让我了解，不需要清洗动作）；
2. needs_clarification：只针对「单位列里 MG 与 mg 是否属于同一单位、是否应统一写法」这个不确定点，向我提一个具体问题。不要对成绩列提交 needs_clarification；
3. propose_cleaning：针对成绩列的 999（本批已确认的缺考码），给出 comparisonCode="999" 的试算建议：checkId=range-rules、columns=["成绩"]、suggestion.action="review_range_violations"，并原样引用本轮 run_checks 返回的 evidenceId。
```

### 3.4 备用提示词（万一这轮没给出可试算建议；实测 19 秒）

```text
这份科研问卷有 10 行数据。本轮只处理一个字段：成绩。
本批数据字典已经确认：成绩的允许范围是 0–100 分，999 表示缺考码。
请严格按以下步骤执行，不要提交 needs_clarification，也不要检查其他字段：
1. 先调用 plan_checks，只提交一项：checkId=range-rules，targetColumns=["成绩"]。
2. 等我确认计划后，调用 run_checks 执行这一项（只查成绩列）。
3. 然后调用 submit_issue 提交一条 propose_cleaning：
   checkId=range-rules、columns=["成绩"]、comparisonCode="999"、
   suggestion.action="review_range_violations"、suggestion.columns=["成绩"]，
   并原样引用 run_checks 返回的 evidenceId。
4. 提交完用一句话总结即可。
```

## 四、分镜时间轴

| 时间 | 画面 / 操作 | 台词要点 |
| --- | --- | --- |
| 0:00–0:20 | 停在数据导入页 | 作品定位：科研数据「想用 AI，又不敢上云」 |
| 0:20–1:00 | 拖入 `fixture.csv` → 数据预览、列画像 | 本地解析、原始数据不出浏览器 |
| 1:00–1:45 | 侧栏「质量检查」→ 8 项检查、覆盖地图 | 检查在本地 Worker 跑；覆盖地图如实标缺口 |
| 1:45–2:40 | 粘贴字典 → 提取（4 条）→ 逐条核对 → 确认 → 「去 AI 分析」 | AI 只抽候选，采用与否由本地校验和人决定 |
| 2:40–4:05 | 输入提示词 → 开始分析 → 「去确认计划」→ 按此计划执行 → 「去审阅」→ 三种决定同屏 → 「人工核对」标记一条 → 展开「核对依据」 | 计划可干预；三种处理决定；核对只记录「人看过」 |
| 4:05–5:15 | 可试算卡（没有「接受」）→ 「对比清洗口径」→ 试算 → 选「转为缺失」+ 理由 → 采用 → 「执行清洗（1 条）」 | 两种口径可比较；口径由人选、理由留痕；执行才改数据 |
| 5:15–6:00 | 「查看报告」→ 报告与导出页 | 可读报告、Word/打印、CSV/留痕 JSON/pandas 脚本；指标看板 |
| 6:00–6:35 | 停在报告页 | 评测数字 + 诚实边界 + 收尾金句 |

> 复盘提示：如果分析超过 60 秒，**不要重复点按钮**，用台词填满等待；真实模型有时会先弹追问面板，按第六节替换台词。

## 五、完整台词（照念版，约 1000 字）

### ① 0:00–0:20 开场

> 这是一个面向高校科研团队的数据质量治理 Agent。做科研数据的人常说一句话：想用 AI，但不敢把数据传上去。我们的做法是：**数据一行都不出浏览器**，AI 只接收结构摘要；每一步判断都能在本地找到依据、由人来确认。

### ② 0:20–1:00 导入

> 先导入一份合成的问卷数据，十行四列。文件在浏览器里解析，预览、编码、列画像都是本地算的。页面上这句「原始数据不会上传到任何服务器」不是文案——代码里出站只有统计摘要和脱敏后的形状。

### ③ 1:00–1:45 检查与覆盖地图

> 八项确定性检查都在本地 Worker 里跑，计算期间界面不冻结。重点看这张覆盖地图：它按字段列出「已完成检查 / 尚未覆盖 / 下一步」，语义模型降级、值域没配置、跨表不支持，都会如实写成没覆盖——**没有发现问题，不等于所有检查都做过**。

### ④ 1:45–2:40 数据字典

> 现实里的数据字典是文档，不是规则。这里粘贴字典原文，AI 只负责从原文里抽候选：范围、允许值清单、缺失占位码。注意候选摘要会按类型计数——这次是 4 条，范围 1、允许取值 2、缺失码 1；每条都要能逐字找到原文出处。勾选确认后才生效，而且只重检被确认的列。看，成绩的越界、学历的不在允许清单，马上就报出来了——**AI 提候选，能不能用得由本机说了算**。确认后可以直接点「去 AI 分析」。

### ⑤ 2:40–4:05 AI 分析

> 接下来是 AI 分析。先让它提交检查计划，我可以取消不需要的项；确认后它只能执行我勾选的检查和字段。这一轮里会同时出现三种处理决定：一条仅展示的、一条需要我先核对口径的（单位列）、一条有本地证据、建议我预览清洗的（成绩列）。
>
> 先看「仅展示」这条：它说明本批口径，不会加入清洗队列。再看「待核对」这条：点一下「人工核对」，写上备注，标记为已核对——注意，**这只记录「人看过」，不改数据，也不解除该字段本轮的清洗限制**。每条结论都能展开「核对依据」：本地检查、涉及哪些行，点行号能直接定位到原表；AI 自己的解释文字会单独标「待核对」——**系统只验证结构化引用，不替模型背书**。

### ⑥ 4:05–5:15 清洗口径对比与执行

> 现在处理成绩的 999。这条建议没有「接受」按钮，因为它只是人工核对类动作——接受只会记录、不会改数据；要清洗必须先选口径。展开「对比清洗口径」，按原写法试算两种处理：转为缺失、或者保留并标记复核。这里能直接看到有效样本、缺失率、均值的变化。我选择「转为缺失」、填上理由——**采用之后还要单独点执行清洗**，才会真正改数据。执行后界面会告诉我改了几个单元格、删了几行，报告和留痕里会记下这次口径、理由和两种口径的统计。

### ⑦ 5:15–6:00 报告与导出

> 点「查看报告」进入报告与导出页：可读报告、Word、打印，清洗后的 CSV、处理留痕 JSON，以及一份与界面行为等价的 pandas 脚本；指标看板里有各层评测的判据与达标线，还有一组「有无 RAG」的配对对照——结论不好看也照实写，比如加了检索之后，暂缓判断这一项反而变差了。

### ⑧ 6:00–6:35 收尾

> 评测方面，L1 检查精确率 93.3%、召回 100%；L3 检索前五命中 100%；性能在五万行五十列的预算内。我们也如实写下不足：Agent 层还有 3/12 的轮次截断，知识库 178 条里团队已核对 104 条，跨表检查还没做。这个作品的取舍很明确：**把可信和可核对放在炫技前面**。

## 六、逐屏点击清单（录制时看这张）

1. 打开 `https://www.ai-web.me/import`（提前 warm 过）。
2. 拖入/选择 `fixture.csv` → 出现「数据预览」「共 10 行 × 4 列」。
3. 点左侧「质量检查」。
4. 展开「从数据字典生成检查规则」→ 粘贴 4 行字典 → 点「AI 提取候选规则」。
5. 看候选摘要（应为 4 条、含缺失占位码 1）→ 逐条勾选 → 点「确认并应用所选规则」。
6. 看到成功提示后点 **「去 AI 分析」**。
7. 在输入框粘贴分析提示词 → 点「开始分析」。
8. 出现提示条 **「检查计划已就绪，等待你确认」** → 点「去确认计划」→ 点「按此计划执行」。
9. 等分析完成 → 点 **「去审阅」**。
10. 在「发现的问题」里：
    - 「仅展示」那条只念；
    - 「待核对」那条点 **「人工核对」** → 写一句备注 → 点「标记为已核对」；
    - 展开任意一条的「核对依据」→ 点一个「定位第 N 行」。
11. 找到「成绩 999」那条（带「对比清洗口径」、**没有「接受」按钮**）→ 展开「对比清洗口径」→ 点「试算两种口径」。
12. 选「转为缺失」→ 在「选择理由」写「已与课题组确认：999 为缺考」→ 点 **「采用此口径」**。
13. 点底部 **「执行清洗（1 条）」** → 等结果「已应用 1 条动作、改动 1 个单元格」。
14. 点结果里的 **「查看报告」** → 停在报告页讲完收尾。

## 七、异常替换台词（遇到就换一句，不要慌）

| 现象 | 替换台词 / 处理 |
| --- | --- |
| 字典候选少于 4 条 | “模型可能漏提，我重提一次；漏掉的规则也可以手动补——这里本来就是人核对 AI。”重提一次；仍缺就继续，但后面可能没有「对比清洗口径」 |
| 弹出追问面板 | 普通追问：选一个选项或“跳过，按现有信息继续”；如果有 **「这题涉及本批口径」** 区块：选「缺失占位码」→“直接确认口径并重新分析”，然后说“系统用新口径重开了一轮，结论和口径版本是绑定的” |
| 分析结束但没有可试算建议 | 不要硬讲。点列表上方的 **「让 AI 重新给出清洗建议」**（按当前口径重开一轮）；仍不理想再用 3.4 备用提示词重来 |
| 状态筛选把待确认建议藏了 | 点筛选栏的“还有 N 条待确认清洗建议，显示”，说“筛选只是视图，不会丢结论” |
| 可试算卡片没有“接受”按钮 | “这条是人工核对类动作，直接接受只会记录、不会改数据；所以这里要求先选清洗口径。” |
| 出现一次红色「失败 / 已拦截」 | “这是模型在一步里混用了工具，被执行器拦下了，它会自动纠正。”继续等，剪辑可跳过 |
| AI 分析超过 60 秒 | “它在多轮工具调用里，每轮一次请求，我们等它跑完。”不要重复点按钮 |
| 线上打不开 | 切到 `http://localhost:3000`，说“我们准备了本地兜底演示，流程完全一致”；详见 §8.31 |

## 八、录后自检

- [ ] 时长 **5–8 分钟**、1080p、普通话真人出镜/口播（规则要求）
- [ ] 画面无 API Key、无控制台报错、无真实个人信息；数据是合成示例
